# @zentauri-ui/zentauri-components

[![npm version](https://img.shields.io/npm/v/@zentauri-ui/zentauri-components)](https://www.npmjs.com/package/@zentauri-ui/zentauri-components)
[![npm downloads](https://img.shields.io/npm/dm/@zentauri-ui/zentauri-components)](https://www.npmjs.com/package/@zentauri-ui/zentauri-components)

A React UI kit for building product interfaces with Tailwind CSS. Components are implemented in TypeScript, ship with declaration files, and are bundled as ESM and CommonJS for broad bundler compatibility.

## Overview

The library targets **React 18+** apps that use **Tailwind CSS v4** (or an equivalent setup where Tailwind can scan this package via `@source`). Styling uses utility classes; **class-variance-authority** powers variant APIs (size, appearance, and similar props), with **clsx** and **tailwind-merge** for predictable `className` composition. Component variants are light-theme ready by default and include paired `dark:` Tailwind classes for dark-mode surfaces, text, borders, focus rings, gradients, and form controls. **Framer Motion** backs motion where a feature ships animated variants, and **react-icons** is used for iconography where applicable.

Published artifacts live under `dist/`. Imports use **per-entry subpaths**: `@zentauri-ui/zentauri-components/ui/<area>` for static UI, `@zentauri-ui/zentauri-components/ui/<area>/animated` where a motion bundle exists, `@zentauri-ui/zentauri-components/animations/<name>` for standalone Motion wrappers, `@zentauri-ui/zentauri-components/charts/<type>` for Recharts-powered chart primitives, and `@zentauri-ui/zentauri-components/hooks/<entry>` for React hooks (and shared helpers under `hooks/utils`). Base UI entries do **not** re-export animated components; motion lives on its own entry so optional `framer-motion` usage stays tree-shakeable and chunk-friendly. Each entry resolves to its own ESM (`.mjs`), CJS (`.js`), and types (`.d.ts`) so bundlers pull only what you import. Most apps rely on Tailwind scanning the package sources (see installation); a separate CSS import is not required for that setup.

For server-side change impact analysis, import `buildChangeImpactGraph`, `analyzeChangeImpact`, and `getChangeImpactPath` from `@zentauri-ui/zentauri-components/ui/change-impact-explorer/graph`. This pure entry has no client boundary; the component entry remains a client entry.

## Package exports

| Subpath                                               | Description                                                                                                                                                                                |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `@zentauri-ui/zentauri-components/ui/<name>`          | Single UI area: static primitives, compound parts, variants, and types. Does **not** include Framer Motion–based animated exports.                                                         |
| `@zentauri-ui/zentauri-components/ui/<name>/animated` | Motion entry for that area when published: animated components, motion presets, and related types (depends on **framer-motion**).                                                          |
| `@zentauri-ui/zentauri-components/animations/<name>`  | Standalone Motion wrapper and preset entry for reusable transitions such as `fade-in`, `scale-in`, and `blur-out` (depends on **framer-motion**).                                          |
| `@zentauri-ui/zentauri-components/charts/<type>`      | Responsive Recharts chart entry for `area`, `bar`, `stacked-bar`, `radar`, `scatter`, `bubble`, `funnel`, `line`, or `pie`, with shared variants, palettes, and exported chart prop types. |
| `@zentauri-ui/zentauri-components/hooks/<entry>`      | One hook module or `utils` (`cn`, `clampPage`, `range` from `src/lib/utils.ts`). Entries match files under `src/hooks/` (see **React hooks**).                                             |

The UI `<name>` segment matches the folder under `src/ui/` (for example `accordion`, `select`, `empty-state`, `buttons` for `Button`, `inputs` for `Input`, `typography` for `Heading` / `Text` and related primitives). The hooks `<entry>` is the file stem (for example `useMediaQuery`, `usePagination`) or `utils`.

Only a subset of UI areas publish a `/animated` entry (see **Components**). Some motion entries also re-export non-motion pieces from the same feature so you can import one motion subpath for a whole flow; others pair a base `ui/<name>` import with a small set of `*Animated` exports from `ui/<name>/animated`—use the `animated/index.ts` for that area as the source of truth.

## Animated components (`ui/<name>/animated`)

- **Why a separate subpath:** animated modules import **framer-motion**. Keeping them on `…/ui/<name>/animated` avoids pulling motion into pages that only use the static `…/ui/<name>` entry and keeps server/client boundaries predictable in app routers.
- **When to install `framer-motion`:** add it when your app imports any `@zentauri-ui/zentauri-components/ui/*/animated` path (see **Optional: animations, icons, and charts** under installation).

Published motion entries (same `<name>` as the base UI folder):

`accordion`, `alert`, `avatar`, `badge`, `buttons`, `card`, `checkbox`, `command`, `copy-button`, `divider`, `drawer`, `empty-state`, `inputs`, `kbd`, `modal`, `popover`, `progress`, `radio-group`, `skeleton`, `spinner`, `table`, `tabs`, `timeline`, `toast`, `toggle`, `tooltip`, `tree-view`

**Spinner:** only the motion entry is built—import from `@zentauri-ui/zentauri-components/ui/spinner/animated` (there is no separate `ui/spinner` static bundle).

## Animations

Standalone animations live outside `ui/*` under `@zentauri-ui/zentauri-components/animations/<name>`. They are small **framer-motion** wrappers around `motion.div`, designed for composing page sections, cards, panels, list items, and route-level content without coupling the motion preset to a UI primitive.

**Animation entries:** `fade-in`, `fade-out`, `fade-up`, `fade-down`, `fade-left`, `fade-right`, `scale-in`, `scale-out`, `pop-in`, `blur-in`, `blur-out`, `slide-up`, `slide-down`, `slide-left`, `slide-right`, `reveal-up`, `reveal-down`, `reveal-left`, `reveal-right`, `reveal-blur`, `text-reveal`, `text-shimmer`, `rotate-in`, `pulse`, `ping`, `shake`, `bounce`, `wiggle`, `float`, `spin`, `flip`, `flip-in`, `tilt`, `magnetic`, `hover-lift`, `hover-scale`, `press`, `reorder`, `skeleton-shimmer`, `progress`, `parallax`.

Each entry exports a named component and its preset object, for example `FadeIn` and `fadeInPreset`. Components accept regular `HTMLMotionProps<"div">`, so you can pass `className`, `transition`, `initial`, `animate`, `exit`, and accessibility attributes directly.

For lighter customization without replacing the whole Motion target, pass `from`, `to`, and `exitTo`. These override preset values for `opacity`, `x`, `y`, `scale`, `scaleX`, `scaleY`, `rotate`, `rotateX`, `rotateY`, and `blur`.

```tsx
import { FadeIn } from "@zentauri-ui/zentauri-components/animations/fade-in";
import { ScaleIn } from "@zentauri-ui/zentauri-components/animations/scale-in";

export function MotionPanel() {
  return (
    <FadeIn className="rounded-xl border border-white/10 bg-white/5 p-4">
      <ScaleIn
        from={{ scale: 0.92, blur: 8 }}
        to={{ scale: 1, blur: 0 }}
        transition={{ duration: 0.2 }}
      >
        Content with a nested scale entrance.
      </ScaleIn>
    </FadeIn>
  );
}
```

## Typography

Import from `@zentauri-ui/zentauri-components/ui/typography`. This entry is **static only** (no `/animated` subpath).

**Components:** `Heading`, `Text`, `List` (with `List.Item`, also exported as `ListItem`), `Blockquote`, `InlineCode`, `CodeBlock`, `Strong`, `Emphasis`, `Small`, `VisuallyHidden`, `Prose`, `TextLink`, and the `DescriptionList` compound family.

**Types:** `HeadingProps`, `TextProps`, `ListProps`, `ListItemProps`, `BlockquoteProps`, `InlineCodeProps`, `CodeBlockProps`, `StrongProps`, `EmphasisProps`, `SmallProps`, `VisuallyHiddenProps`, `TypographyControls`, `HeadingLevel`, `TextElement`, `TypographyTone`, `UnorderedMarker`.

**Tone (`tone` prop):** `default`, `muted`, `primary`, `secondary`, `accent`, `destructive`, `info`, `success`, `warning`, `error`, and gradient presets: `gradient-pink-violet`, `gradient-cyan-violet`, `gradient-cyan-blue`, `gradient-cyan-green`, `gradient-cyan-orange`, `gradient-cyan-red`, `gradient-cyan-purple`, `gradient-cyan-pink`. Tones align with kit accent colors (slate / cyan / violet baseline).

**Blockquote:** Optional `attribution` renders a footer label (separate from the HTML `cite` attribute).

**Code samples:** `InlineCode` styles inline `code`; `CodeBlock` renders a `pre` with an inner `code` (pass string or fragment children, not another `code` element) and optional `language` for `aria-label`.

**CVA helpers (composition):** `headingLevelVariants`, `headingFluidVariants`, `headingDisplayVariants`, `headingFluidDisplayVariants`, `textSizeVariants`, `textPresetVariants`, `typographyStyleVariants`, `typographyFontVariants`, `typographyToneVariants`, `unorderedListMarkerVariants`, `orderedListVariants`.

### Scale, presets and accessible inline text

Heading and Text support logical `align` (`start`, `center`, `end`, `justify`), `weight` (`normal`, `medium`, `semibold`, `bold`), `leading` (`tight`, `normal`, `relaxed`), `tracking` (`tight`, `normal`, `wide`), `wrap` (`normal`, `balance`, `pretty`, `nowrap`) and `measure` (`none`, `readable`, `wide`). Explicit normal/balance/pretty wrapping also breaks oversized words when necessary. Omitted controls retain current defaults. Text also supports `font` (`body`, `mono`) and `numeric` (`normal`, `tabular`).

Heading `level` always chooses the semantic tag. `displaySize` (`sm`, `md`, `lg`) overrides `displayLevel` for visual sizing. `scale="fluid"` is opt-in; the default preserves existing heading sizes, including h1's md breakpoint.

Text `preset` is `body`, `lead`, `caption`, or `overline`. Explicit size, weight, leading and tracking override presets; explicit weight overrides the legacy `bold` flag. Overline supplies its own weight; `bold` still applies to presets that do not specify one. Uppercase styling does not change the text string. `className` remains the final utility override, with responsive variants following normal Tailwind rules.

```tsx
<Heading level={2} displaySize="sm" scale="fluid" wrap="balance">A semantic section heading</Heading>
<Text preset="lead" measure="readable">Introductory copy.</Text>
<Text preset="caption" tone="muted">Supporting detail.</Text>
<Text preset="overline">Product update</Text>
<Text font="mono" numeric="tabular">12,345.67</Text>
<Text as="label" htmlFor="email">Email</Text>
<Text tone="muted"><Strong>Important</Strong> <Emphasis>stress</Emphasis> <Small>fine print</Small></Text>
<button><span aria-hidden="true">×</span><VisuallyHidden>Close</VisuallyHidden></button>
<VisuallyHidden focusable><a href="#content">Skip to content</a></VisuallyHidden>
<div id="content" tabIndex={-1}>Content target</div>
```

Strong, Emphasis and Small use native strong/em/small elements and inherit surrounding text color unless a tone is supplied. Existing Text bold/italic/highlight flags remain visual conveniences. VisuallyHidden keeps content available to assistive technology; focusable reveals the wrapper on focus-within and does not create a tab stop. A skip link needs a real target. These additions retain the typography client entry and support prerendering; they do not introduce a dedicated server-only export.

### Scoped typography tokens

### Rich content, links and definition lists

`Prose` styles already-rendered HTML or MDX children; it is not a Markdown parser. It accepts `as="div" | "article"`, `size="sm" | "base" | "lg"`, `measure="readable" | "wide" | "none"`, and non-gradient text tones. The default is a div with base sizing and readable width. Zero-specificity descendant selectors let native elements keep explicit utility overrides. Elements with component data-slots and `data-prose="ignore"` subtrees skip those selectors; container fonts/colors still inherit. Nest wide tables in an `overflow-x-auto` wrapper to preserve table semantics. Existing CodeBlock and Kbd entries can be embedded without adopting raw prose styles.

`TextLink` uses a native anchor and preserves href, download, ref and other native props. Underline is always visible by default, with hover/focus or none alternatives. Its decorative `externalIndicator` does not change target or accessible name. Set `target="_blank"` explicitly; the component merges noopener into rel while retaining supplied tokens. Add explicit accessible text for a new-tab announcement when desired. Only non-gradient tones are available.

`DescriptionList` renders dl/dt/dd with `Item`, `Term` and `Details` compound members and equivalent named exports. Layout is responsive by default (stacked below md, two columns from md); stacked/inline layouts and optional separators are available. Multiple Details members can follow one Term. Column proportions, gaps, separator colors and weights are themeable. Nested definition lists configure their own layout.

```tsx
<>
<Prose as="article">
  <h2>Release notes</h2>
  <p>Already-rendered content receives a consistent rhythm.</p>
  <div data-prose="ignore"><p className="text-sm">Embedded panel</p></div>
</Prose>
<TextLink href="/docs">Read docs</TextLink>
<DescriptionList separators>
  <DescriptionList.Item>
    <DescriptionList.Term>Documentation</DescriptionList.Term>
    <DescriptionList.Details><TextLink href="/docs">Read docs</TextLink></DescriptionList.Details>
  </DescriptionList.Item>
</DescriptionList>
</>
```

Additional exports include `ProseProps`, `TextLinkProps`, `ReadableTypographyTone`, `DescriptionListProps`, `DescriptionListItemProps`, `DescriptionListTermProps`, `DescriptionListDetailsProps`, and `proseVariants`, `textLinkVariants`, `descriptionListVariants`.

For framework navigation, apply `textLinkVariants()` to the consumer's Link rather than nesting anchors. With Next.js, call that helper inside a client component because the typography entry retains its client boundary. No Next.js or Motion dependency is introduced into the library. ### useDebouncedCallback

```tsx
import { useDebouncedCallback } from "@zentauri-ui/zentauri-components/hooks/useDebouncedCallback";

const { debouncedCallback, cancel, flush, isPending } = useDebouncedCallback(
  (draft: string) => saveDraft(draft),
  600,
);
// Call with plain values in an event/effect, never during render.
debouncedCallback("Latest draft");
cancel(); // Discard scheduled work.
const result = flush(); // Run scheduled work now, or undefined if idle.
```

Trailing-only debounce: every call restarts the timer with the latest arguments. The three control functions keep stable identities and invoke the latest committed callback. `isPending` is reactive scheduled-timer state, not async request status. Handle async errors inside the callback; `flush` exposes its result/Promise, while a scheduled call has no synchronous result. Cancel does not abort an in-flight request.

`delayMs` must be finite and between 0 and 2,147,483,647 inclusive. Zero defers work to a timer. Changing the delay affects future calls without moving an existing deadline. Unmount discards pending work without flushing. Leading calls and max-wait are outside this API. Use `useDebouncedValue` when you need derived state rather than a delayed action.

Preview: `/preview/hooks/use-debounced-callback`. Vendor with `zentauri-ui add hook useDebouncedCallback`; the CLI includes its `useIsomorphicLayoutEffect` dependency.

## CLI — copy component source into your app

The package ships a small **Node CLI** (`zentauri-components` and `zentauri-ui` point to the same `cli/index.mjs`) that copies **selected** folders from this package’s `src/ui`, `src/animations`, `src/charts`, and `src/hooks` into your repository—similar to shadcn/ui. You keep the files, control paths via `components.json`, and imports are rewritten to your path aliases (`@/components/ui`, `@/components/animations`, `@/hooks`, `@/lib/utils`, and so on).

Which UI folders are valid for `add` is driven by **`cli/registry.json`**: a generated manifest listing every addable directory name (matching `src/ui/<name>`, animation entries like `animations/fade-in`, plus chart entries like `charts/area`) plus optional **`nameAliases`** so the CLI accepts friendly tokens (for example `button` → `buttons`).

### Commands

Call the published binary by name after the package (recommended so `npx` does not treat the first word as a shell command):

```bash
npx @zentauri-ui/zentauri-components init
npx @zentauri-ui/zentauri-components add buttons inputs
npx @zentauri-ui/zentauri-components add animations/fade-in
npx @zentauri-ui/zentauri-components add charts/area charts/line
npx @zentauri-ui/zentauri-components -h
```

**Hooks only** (copy `src/hooks/<name>` into your app, plus sibling hook dependencies such as `useMediaQuery` when needed):

```bash
npx @zentauri-ui/zentauri-components add hook useWindowSize
npx @zentauri-ui/zentauri-components add hook useToggle useDebouncedValue
```

The **`zentauri-ui`** binary is the same entry as **`zentauri-components`**. If `npx` still mis-resolves, pin the package:

```bash
npx --yes --package=@zentauri-ui/zentauri-components zentauri-components init
npx --yes --package=@zentauri-ui/zentauri-components zentauri-components add button
```

From a monorepo checkout you can run the script by path instead of `npx`:

```bash
node node_modules/@zentauri-ui/zentauri-components/cli/index.mjs init
node node_modules/@zentauri-ui/zentauri-components/cli/index.mjs add accordion
node node_modules/@zentauri-ui/zentauri-components/cli/index.mjs add hook useWindowSize
```

| Command               | What it does                                                                                                                                                                                                                                                                                                                                                                              |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `init`                | Writes **`components.json`** in the current working directory (or `--cwd`) with default `aliases` and `resolvedPaths`. Refuses to overwrite an existing file.                                                                                                                                                                                                                             |
| `add <names...>`      | Walks up from `--cwd` (default `.`) to find `components.json`, then copies each resolved **UI** folder under `src/ui` or chart entry under `src/charts/<type>`, pulls in hooks those files depend on (including transitive hook imports), and creates **`lib/utils`** at `resolvedPaths.utils` from the package template if it is missing.                                                |
| `add hook <names...>` | Same config lookup; copies only **hook** folders listed under `registry.hooks` (from `hooksEntryNames` in `tsup.config.ts`), including transitive sibling-hook imports. Does not copy UI unless a hook’s imports require you to add a component separately (for example `usePagination` imports types from `ui/pagination`; `useDynamicStepper` imports types from `ui/dynamic-stepper`). |

Global flags: `-h` / `--help`, `-v` / `--version`, `--cwd <dir>` (relative to `process.cwd()`).

### `components.json` (created by `init`)

Defaults look like this; edit `resolvedPaths` and `aliases` so they match your app’s `tsconfig` / bundler paths.

```json
{
  "aliases": {
    "ui": "@/components/ui",
    "utils": "@/lib/utils",
    "hooks": "@/hooks"
  },
  "resolvedPaths": {
    "ui": "src/components/ui",
    "utils": "src/lib/utils.ts",
    "hooks": "src/hooks"
  }
}
```

### Registry (`cli/registry.json`)

- **`components`**: sorted list of folder names under **`src/ui/`**, plus chart entries from **`src/charts/<type>`**, that `add` may copy. The file is **generated**; the canonical build lists live in **`tsup.config.ts`** as `uiComponentNames`, `uiAnimatedComponentNames`, and `chartEntryNames`, so animated-only entries such as **`spinner`** stay aligned with the CLI.
- **`hooks`**: sorted list of folder names under **`src/hooks/`** that `add hook` may copy; generated from **`hooksEntryNames`** in **`tsup.config.ts`** (same entries as published `…/hooks/<name>` subpaths).
- **`nameAliases`**: optional map from a CLI token to a real folder name: `button` → `buttons`, `input` → `inputs` (singular forms while folders stay plural), and `chart-<type>` → `charts/<type>` for every chart (so `add chart-line` and `add charts/line` are equivalent).
- **`peerHints`**: generated map from a component/chart name to the **optional peer dependencies** its source imports (`framer-motion` for components that ship an `animated/` variant, `react-icons` where icons are used, `recharts` for every chart). After `add`, the CLI prints a deduplicated install hint built from this map, so you never have to guess which peers a vendored component needs.

Example: these are equivalent when `nameAliases` is configured:

```bash
zentauri-components add button
zentauri-components add buttons
```

After `add`, imports inside copied `.ts`/`.tsx` files are rewritten using your `aliases`; test files (`*.test.*`, `*.spec.*`) from the package are not copied.

### Worked examples

```bash
# A static UI primitive — copies src/ui/buttons plus the shared design-system tokens it imports.
zentauri-ui add button

# A chart — copies src/charts/line and the shared chart frame; CLI hints `recharts`.
zentauri-ui add charts/line

# A hook on its own — copies src/hooks/useClipboard (plus any sibling hooks it imports).
zentauri-ui add hook useClipboard
```

### Vendored destination structure

Given the default `components.json`, running `zentauri-ui add button charts/line` then `add hook useClipboard` produces:

```
your-app/
├── components.json
└── src/
    ├── components/
    │   ├── design-system/        # shared token + variant strings (copied once, never overwritten)
    │   │   └── button.ts
    │   └── ui/
    │       ├── buttons/          # the component folder (index.ts, button.tsx, variants.ts, …)
    │       └── charts/
    │           ├── shared/       # chart frame + helpers shared by every chart
    │           └── line/         # the requested chart entry only
    ├── hooks/
    │   └── useClipboard/         # hooks pulled in by components or `add hook`
    └── lib/
        └── utils.ts              # cn() helper, created from the package template if missing
```

- `design-system/` lands beside `ui/` (one level up from `resolvedPaths.ui`) so vendored components keep their `../../design-system/*` imports working without a new alias. Existing files there are left untouched on re-add.
- Charts always land under `<ui>/charts/`, with a single shared `charts/shared/` folder regardless of how many chart types you add.
- Re-adding a component overwrites that component's files but preserves your `design-system/` and `lib/utils.ts` edits.

### When to use the CLI vs npm imports

| Approach                                         | Best when                                                                                                                   |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| **`npm` + package `exports`** (earlier sections) | You want versioned dependencies, smallest app-owned surface, and tree-shaken `dist/` entries.                               |
| **`init` / `add`**                               | You want vendored source under your repo (customize primitives, match shadcn-style workflows, or lock file-level behavior). |

Tailwind still needs to see the classes your **copied** files use—point `@source` at those paths (for example your `src/components/ui`) rather than only at `node_modules/@zentauri-ui/zentauri-components` if you no longer rely on scanning the published package. This matters for the light/dark variant pairs too: copied components keep their base light utilities and `dark:` overrides, and both need to be included in Tailwind's generated CSS.

## Accessibility checklist for contributors

Every new or changed component should clear this bar before it merges. The
highest-risk primitives (overlays and keyboard-heavy controls) are expected to
have explicit tests for the items below.

**Semantics & ARIA**

- [ ] Correct landmark/role for the pattern (`dialog`, `menu`/`menuitem`, `listbox`/`option`, `tab`/`tabpanel`, `slider`, `tree`/`treeitem`, …).
- [ ] State is announced: `aria-expanded`, `aria-selected`, `aria-checked`, `aria-disabled`, `aria-current` as appropriate.
- [ ] Overlays set `aria-modal` and wire `aria-labelledby` / `aria-describedby` to the rendered title/description.
- [ ] Compound parts are linked by id (`aria-controls`, `aria-haspopup`) rather than relying on DOM proximity.

**Keyboard**

- [ ] All interactive parts are reachable and operable by keyboard (Enter/Space activate; Arrow keys navigate where the role implies it).
- [ ] Roving tabindex for composite widgets (one tab stop; arrows move within).
- [ ] Dismissible surfaces close on `Escape`.
- [ ] Focus moves into an opened overlay and **returns to the trigger** on close.

**Disabled & edge states**

- [ ] Disabled items are skipped by keyboard navigation and ignore pointer activation, and expose `aria-disabled`.
- [ ] SSR-safe: no access to `window`/`document` during render (guard effects; the package targets React 18+ server rendering).

**Motion**

- [ ] Animated entries respect `prefers-reduced-motion` (use `usePrefersReducedMotion` / Framer Motion's `useReducedMotion`).
- [ ] `framer-motion` stays out of static entries — enforced by `src/ui/peer-isolation.test.ts`. Charts stay isolated to `src/charts/*`.

Add or extend the component's `*.test.tsx` to cover the items that apply; see
`modal`, `select`, and `context-menu` tests for worked examples.

## Typography text utilities

Import `Mark`, `HighlightText`, `TruncateText` and `ExpandableText` from the existing `ui/typography` entry, or vendor the family with `zentauri-ui add typography`. Vendoring also includes the disclosure's `useTextOverflow` and `useControllableState` dependencies.

```tsx
import { HighlightText, TruncateText, ExpandableText } from "@zentauri-ui/zentauri-components/ui/typography";

<HighlightText text="A literal [match] in the result" query={["[match]", "result"]} />;
<TruncateText as="p" lines={2}>The complete string remains in the DOM.</TruncateText>;
<ExpandableText text={description} lines={3} moreLabel="Read more" lessLabel="Read less" />;
```

- `Mark` renders semantic relevance markup with paired `--zui-typography-mark-*` colors, padding and radius. It does not automatically announce mark boundaries.
- `HighlightText` accepts a string and literal query/query array. It ignores empty queries, uses leftmost nonoverlapping matches and prefers the longest match at the same start. Case-insensitive matching uses Unicode simple case folding, without accent normalization or locale-specific equivalence; `caseSensitive` opts out. Original text, casing, whitespace and emoji are retained. `markClassName` styles matches. No HTML parsing or arbitrary child traversal occurs.
- `TruncateText` renders span/p/div with string children; `lines` must be a positive integer (default 1). One line uses ellipsis, multiple lines use CSS clamping. The inline line count is explicit API state, not a theme token. It does not add a title or tooltip. The full string remains copyable and accessible. Its span uses block layout to permit width-constrained clipping.
- `ExpandableText` is a div with a text area and native button. It supports `expanded`, `defaultExpanded`, `onExpandedChange`, localized `moreLabel`/`lessLabel`, `contentId`, `contentClassName` and `buttonClassName`. By default, the button appears only when the collapsed layout overflows and remains available after expansion. A stable content node/ID preserves focus and connects `aria-controls`/`aria-expanded`. Expansion changes visual presentation; clipped text remains in the accessibility tree. `showToggle="always"` renders the button unconditionally, including when content fits, and skips layout measurement. Initial measured-mode rendering contains full clamped text without a button, and the button may appear after mount.

### useTextOverflow

```tsx
import { useTextOverflow } from "@zentauri-ui/zentauri-components/hooks/useTextOverflow";

const { ref, isOverflowing, hasMeasured, remeasure } = useTextOverflow<HTMLDivElement>({
  measurementKey: description,
  lines: 3,
  tolerance: 1,
});
```

Attach the callback `ref` to the text container. `enabled` defaults to true; `axis` accepts horizontal/vertical/both (default both). Without `lines`, the hook compares the actual scroll/client dimensions. With `lines`, it measures a temporary text-only copy at the source computed width/styles, constrained to the requested collapsed line count. The copy has no source IDs, attributes, markup or event handlers; it is hidden/inert and removed immediately. This mode is for plain text, not rich interactive markup.

Measurements run after mount and batch into an animation frame (timer fallback). ResizeObserver, window resize, text/style/ancestor theme mutations, a changed measurement key and font loading schedule new measurements; cleanup disconnects them. No browser layout is read during server render. The initial result is unmeasured; hidden/zero-width containers remain unmeasured until available. `remeasure()` handles changes outside the observed inputs. The default tolerance ignores differences up to 1 CSS pixel to accommodate rounded client/scroll metrics; use a smaller explicit tolerance when needed.

Preview pages: `/preview/typography/highlighting`, `/preview/typography/truncation`, and `/preview/hooks/use-text-overflow`. Static typography imports no Motion dependency.

## Locale-aware numeric typography

`NumberText` lives in the existing `ui/typography` family and reuses its paired font, size, tone, leading, tracking and numeric recipes. Its default is a span with base sizing and tabular digits; native p/div props and refs are supported through `as`. `numeric="normal"` opts out of tabular digits. Native CSS `style` is separate from `formatOptions.style`.

```tsx
import { NumberText } from "@zentauri-ui/zentauri-components/ui/typography";

<NumberText value={1234567.89} locale="en-IN" />;
<NumberText value={1234.5} locale="en-US" formatOptions={{ style: "currency", currency: "USD" }} />;
<NumberText value={1234.56} locale="fr-FR" formatOptions={{ style: "currency", currency: "EUR" }} partClassNames={{ fraction: "text-sm", currency: "font-semibold" }} />;
```

Optional `partClassNames` styles native formatter parts. Every part's original text/order is retained, including grouping, signs, decimal separators, literals and currency spacing. Without part styles, NumberText renders the formatted string directly. Values must be numbers or bigint; numeric strings are rejected rather than parsed. Bigint stays exact without a number conversion. NaN, infinities and negative zero use native localized output; applications can validate inputs or supply a separate empty/error state.

### useNumberFormat

```tsx
import { useNumberFormat } from "@zentauri-ui/zentauri-components/hooks/useNumberFormat";

const { format, formatToParts, resolvedLocale, formatter } = useNumberFormat({
  locale: "en-IN",
  style: "currency",
  currency: "INR",
});
```

The default and final locale-preference fallback is **en-US**, including an empty locale array. No browser language or geolocation is read. Pass an explicit locale for server-rendered examples; exact output also depends on matching Intl locale data across environments. Invalid locale syntax and invalid Intl options retain native errors.

`getCachedNumberFormat(locale?, options?)` is also exported. It canonicalizes locale preferences and snapshots standard option keys in a fixed order, omitting undefined options. A FIFO cache holds at most **50 formatter instances**. Unknown keys and nonprimitive/nonfinite option values bypass caching and stay under native construction. Failed construction does not evict a valid cached formatter. Hook callbacks remain stable when the cached formatter is unchanged and update when locale/options change.

The convenience `format`/`formatToParts` functions accept number or bigint values. `formatter` is the native Intl object; other native capabilities depend on runtime/type-library support. No formatRange convenience API is promised. The helper is pure JavaScript, but the existing hook entry remains a client boundary in Next.js; this change does not add a server-only package entry.

[Native Intl.NumberFormat](https://tc39.es/ecma402/#numberformat-objects) controls display rounding, currency precision, notation, percentages and units. Formatting never changes the source value and is not a calculation or money-storage API. Static NumberText imports no Motion dependency. The docs show a separate decorative integer AnimatedNumber composition with localized accessible text; they do not claim that digit animation supports localized currency or units.

Preview pages: `/preview/typography/number-formatting` and `/preview/hooks/use-number-format`. `zentauri-ui add typography` vendors the number-formatting hook transitively; `zentauri-ui add hook useNumberFormat` adds it on its own.

## Editorial typography

The existing `ui/typography` entry exports `Footnotes`, its named subcomponents, `estimateReadingTime` and two class-string recipes: `typographyPermalinkRecipe` and `typographyDropCapRecipe`. No Motion or content-parser dependency is added.

```tsx
import { Footnotes } from "@zentauri-ui/zentauri-components/ui/typography";

<Footnotes scopeId="published-article">
  <p>Opening claim<Footnotes.Reference noteId="source" referenceId="opening" number={1} /></p>
  <p>Repeated citation<Footnotes.Reference noteId="source" referenceId="closing" number={1} /></p>
  <Footnotes.List aria-label="Article notes">
    <Footnotes.Item noteId="source" number={1}>
      Source explanation.
      <Footnotes.Backlink noteId="source" referenceId="opening" label="Back to opening reference" />
      <Footnotes.Backlink noteId="source" referenceId="closing" label="Back to closing reference" />
    </Footnotes.Item>
  </Footnotes.List>
</Footnotes>;
```

Named exports are `FootnotesList`, `FootnoteItem`, `FootnoteReference` and `FootnoteBacklink`. Native div/ol/li/anchor attributes and refs are preserved. References/items/backlinks require a Footnotes root; the list is an ordinary styled ol. Items are native hash focus targets with default `tabIndex={-1}`. Backlinks use native anchors and require meaningful accessible labels. Reference labels default to “Footnote N” and can be localized with `aria-label`; list names use native `aria-label` as well.

Authors own note IDs, reference IDs and matching positive 32-bit note numbers. IDs must be nonempty and whitespace-free. Repeated references to a note use distinct reference IDs, and the note includes one backlink for each. Length-delimited generated IDs and encoded fragments support special/Unicode characters without ambiguous tuples. Footnotes does not allocate numbers, generate a note list or correct missing/duplicate authored targets. Default React IDs separate roots within a React rendering root and stay stable during hydration. For persistent article links, supply a stable unique scopeId. Across independent React roots, supply unique scopes or React identifier prefixes.

### Heading links and drop caps

Compose Heading with an explicit ID and an adjacent TextLink carrying an accessible name. Apply `typographyPermalinkRecipe` to the link inside a `group` container: hover-capable devices reveal it on hover/keyboard focus; touch-style surfaces retain its visibility. Keeping the link outside the heading preserves the heading's text/name. IDs and link labels are authored explicitly; no child-to-slug conversion occurs.

Apply `typographyDropCapRecipe` to an opt-in raw paragraph inside Prose. It styles the native first-letter pseudo-element with paired `--zui-typography-drop-cap-size`, `-leading`, `-gap` and existing display-font variables. Logical floating/spacing follows direction. Punctuation selection follows native CSS; the original text remains selectable and accessible. Review the treatment with the intended script/font and narrow layout rather than applying it globally. These are class-string recipes, not additional paragraph/heading components.

### Plain-text reading-time estimate

Server Components should import the estimator from the pure `ui/typography/reading-time` entry, which has no client boundary. The `ui/typography` client entry also re-exports it for client components.

```tsx
import { estimateReadingTime } from "@zentauri-ui/zentauri-components/ui/typography/reading-time";

const estimate = estimateReadingTime(articleBodyText, {
  wordsPerMinute: 200,
  locale: "en-US",
  mode: "approximate",
});
// { wordCount, minutes, seconds, method }
```

The helper accepts only plain text. It does not parse HTML/Markdown/Lexical data or traverse React children. `minutes` and `seconds` are rounded up independently; empty/punctuation/emoji-only input returns zero. Reading speed defaults to a configurable 200 words/minute product estimate, not a universal reading-rate claim; invalid/nonfinite rates and unsupported duration overflow throw.

`mode="auto"` uses native [Intl.Segmenter](https://tc39.es/ecma402/#segmenter-objects) word-like segments where available and falls back to approximate Unicode letter/number runs, combining marks and internal apostrophes. `mode="segmenter"` requires that feature; `mode="approximate"` pins the fallback strategy. Approximate counting can undercount text in languages without spaces. Locale syntax is validated and en-US is the default/final locale preference. Automatic results can vary with runtime support/locale data; pin approximate mode to remove feature-availability differences, or reuse precomputed results for server/client agreement. Exact Unicode classification still depends on runtime Unicode data.

The estimate composes NumberText with native minute units in the docs. Import estimateReadingTime from ui/typography/reading-time in Server Components or other server code; this dedicated entry has no client directive or React dependency. The existing ui/typography export remains available for client consumers, and the permalink/drop-cap recipes remain in that client entry. Vendored consumers can import the plain reading-time utility source directly. CMS text extraction, editor/schema features and published article adoption remain separate integration work.
